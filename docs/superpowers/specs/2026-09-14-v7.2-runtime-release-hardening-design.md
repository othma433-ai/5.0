# WA Al-Othmany Link Bot v7.2 Runtime & Release Hardening Design

Date: 2026-09-14
Status: Approved for implementation
Target: v7.2.0-rc1

## Goal
Ship a conservative v7.2.0-rc1 hardening release that preserves every working v7.1 feature while improving operation admission safety, navigation probe responsiveness, release reproducibility, diagnostics, and GitHub delivery.

## Runtime changes

### 1. Atomic automation admission
The service must reject overlapping Sync / Extract / Retry starts even if two UI requests arrive before BotRuntime has published the first asynchronous state transition. A session-local operation lease is acquired before asynchronous database work or WhatsApp launch and is released only when the operation is cleared or an early-start path aborts.

### 2. Adaptive bounded navigation probes
Opening/navigation fallback probes must remain event-driven first, but the watchdog fallback must use bounded performance-profile-aware delays instead of fixed `300/350/500 ms` polling loops. FAST probes more aggressively, BALANCED remains the default, SAFE allows longer UI settling time. Each loop remains below the existing stage watchdog deadline.

### 3. Evidence-first execution remains mandatory
No action dispatch is treated as proof of success. Screen/state verification, circuit breakers, durable viewport persistence, queue recovery, deduplication, and existing feature-preservation behavior stay intact.

## Build and GitHub changes

- Add a Gradle 8.9 Wrapper so the repository is self-contained for GitHub Actions and local builds.
- Make CI use `./gradlew` instead of relying on a preinstalled Gradle executable.
- CI must run release audit, unit tests, lint, and `assembleDebug` before publishing an APK artifact.
- Add a tag-triggered GitHub Release workflow that builds the verified APK, computes SHA-256, and attaches both files to the GitHub Release.
- Artifact names must derive from the Gradle `versionName`, avoiding stale hard-coded release names.
- README, project status, device-test checklist, changelog, and release notes must identify v7.2.0-rc1 and distinguish static/JVM verification from physical-device certification.

## Acceptance gates

1. Existing 37-test pure Kotlin suite still passes.
2. New operation-lease and navigation-probe tests pass.
3. `tools/release-audit.sh` passes with v7.2 invariants.
4. Gradle wrapper is present and reports Gradle 8.9.
5. Android unit tests, lint, and APK build pass when Android SDK 35 is available.
6. Generated APK exists and has a SHA-256 checksum if local SDK installation succeeds.
7. No physical-device behavior is claimed as verified without an actual device run.
