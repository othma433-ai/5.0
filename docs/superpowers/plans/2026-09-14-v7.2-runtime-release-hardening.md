# WA Al-Othmany Link Bot v7.2 Runtime & Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a verified v7.2.0-rc1 source/release bundle with safer operation admission, faster bounded navigation fallback, reproducible Gradle builds, and GitHub APK/release automation.

**Architecture:** Preserve the current Accessibility/Room/Coroutine architecture. Add two small pure-Kotlin policies at the service boundary: an atomic operation lease for cross-workflow exclusion and a performance-aware navigation probe policy for fallback polling. Keep runtime actions evidence-driven and integrate release automation without changing user-facing features.

**Tech Stack:** Kotlin 2.0.21, Android/AGP 8.7.3, Gradle 8.9, Java 17 target, Jetpack Compose, Room, Coroutines, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-14-v7.2-runtime-release-hardening-design.md`

## Global Constraints

- Preserve all v7.1 user-facing capabilities.
- Do not introduce arbitrary screen-coordinate logic; gesture fallback may only use bounds of a semantically resolved node.
- No action dispatch counts as success without subsequent state evidence.
- Core operation must not require Shizuku or Root.
- Physical-device certification remains a separate release gate.
- Target release is exactly `versionCode = 72`, `versionName = "7.2.0-rc1"`.
